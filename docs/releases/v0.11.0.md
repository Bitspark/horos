# horos 0.11.0

This release publishes npm, crates.io and the Go module at one version again, on
public Ontos 0.17.0. Every checker now reports where a diagnosis failed and accepts
integer bounds. Recursive descriptors resolve `ref` lexically in every core, which
changes some verdicts. The Go declarations layer changes one verdict, fixes a budget
exhaustion and gains its own test suite.

## Upgrade together: Ontos 0.17.0

Every package requires public Ontos 0.17.0:

- npm: `@bitspark/ontos-core`, `-codec` and `-data` 0.17.0;
- crates.io: `bitspark-ontos-core`, `-data` and `-codec` =0.17.0;
- Go: `github.com/bitspark/ontos v0.17.0`.

The Python validation lane uses the 0.17.0 source. Ontos 0.17.0 is additive. Its
value model, structural identity and `ontos-codec-v1` bytes are unchanged. A
dependency graph still holds a single Ontos version, so upgrade your Ontos
dependencies together with Horos. No adapter, fallback or second value type is
provided.

Bitwire 0.7.0 pins Ontos 0.16.0, so it cannot share a dependency graph with this
release. The consumer qualification no longer installs Bitwire until Bitwire
publishes a release on Ontos 0.17.0. It checks the same ground/mixed boundary
against Ontos's native mixed model and reports the suspension in every run and
in its receipt. See [distribution](../distribution.md).

## Diagnostics name where a check failed (ADR 0009, #37)

Every diagnosis other than `conforms` carries one location:

- a value path into the checked value;
- the position of the descriptor at fault, as written;
- a reason;
- the record field or the malformed argument, where the reason calls for one.

Go, Rust and TypeScript select the same location by one fixed order. Verdicts,
`limit`, the checking profile and the boolean API are unchanged, and a location
never changes a verdict.

- Go: `Diagnosis.Location` (nil for `conforms`).
- TypeScript: `location` on every non-conforming `Diagnosis` variant.
- Rust: `diagnose_located` and `diagnose_wf_located` return `Located`, which
  pairs the unchanged `Diagnosis` with its `Location`. `diagnose` and
  `diagnose_wf` are unchanged.

`vectors/diagnose.json` pins the locations for every core. The source-only Python
validation lane gains `diagnose` and `diagnose_wf` in `horos.diagnose` (#46). It
was written from the form contract and the decision records as a fourth independent
reading, and it replays the location corpus in full. See
[ADR 0009](../architecture/decisions/0009-diagnostic-locations.md) and the
[form contract](../spec/horos.md#diagnostic-locations).

## Integer bounds (ADR 0010, #36)

`int-min(int(lo))` accepts a canonical `int` `v` with `lo <= v`, and
`int-max(int(hi))` one with `v <= hi`. A closed range is their intersection,
`and(int-min(int(0)), int-max(int(9)))`.

- Values keep arbitrary width and compare exactly.
- A bound is a canonical int in the signed 128-bit range, and it may be negative.
- Any other value, including text, a decimal or a non-canonical integer encoding,
  is refused.

A new hand-authored oracle, `vectors/integer-bounds.json`, is replayed by Go, Rust,
TypeScript, Python and the CLI harness. The original oracle stays pinned byte for
byte. See [ADR 0010](../architecture/decisions/0010-integer-bounds.md).

The Go declarations schema recognizes both forms (#42). The bundled `horos.kinds`
standard module does not list them yet, so a Data declaration whose body uses them
is refused with `BoundViolation`. Ground descriptors and the ground checkers accept
them now. The standard module gains them once Bittype's module encoder accepts the
new node constructors and the asset is regenerated.

## Recursion: `ref` resolves lexically (ADR 0011)

A `ref` denotes the `rec` that lexically encloses it in the written descriptor, as
the form contract says and as well-formedness already read it. Every core used to
check an unfolded `rec` body in the environment of the place where it was unfolded,
so an inner `rec` that rebinds a name captured the `ref`s in that body. `conforms`,
`diagnose` and `diagnoseWf` now resolve each `ref` lexically in Go, Rust,
TypeScript and Python. Each binding is a closure over the bindings it was written
under. The name-keyed guard against unguarded unfolding is removed: under lexical
lookup it never fires on a well-formed descriptor, and every check verifies
well-formedness first. Every unfolding still counts against the depth bound of 512,
so a recurring unfolding ends in `exhausted` (or the boolean's bounded `false`),
never a hang. The depth bound, its accounting and the other rules of ADR 0008 and
ADR 0009 are unchanged. There is no flag or mode that keeps the old reading. See
[ADR 0011](../architecture/decisions/0011-lexical-ref-scope.md).

**Verdict change, in both directions.** It affects only a descriptor in which a
`rec` body refers to an outer binding of a name and is unfolded inside an inner
`rec` of the same name. With

```text
T = rec(M, union(exact(a), rec(L, tuple(ref(M), rec(M, union(exact(b), tuple(ref(L))))))))
```

`(a, ((a, b),))` now conforms and `(a, ((b, b),))` is now refused; earlier releases
answered the opposite for both. `diagnose` changes its verdict wherever the boolean
does. A mismatch's location can move to the body of the `rec` the `ref` now
denotes, and an input that mismatched early under capture can now run on to the
depth bound and report `exhausted`. Descriptors without such a capture answer as
before, and no case in the original oracle, the diagnostic corpus or the
integer-bounds oracle changes. A new hand-authored oracle,
`vectors/recursion-scope.json`, pins the lexical judgments and their diagnoses.

## Go declarations

- **Verdict change.** Applying an abstract constructor parameter, such as
  `F: Data => Data`, to a closed argument outside its input contract, such as
  `wire(Person)`, now reports `BoundViolation`. It used to report
  `UnprovedObligation`. Closed membership is exact, so the obligation is refuted.
  The same argument to a known constructor already reported `BoundViolation`.
  (57a230b, #39)
- **Budget fix.** Small higher-order contracts that mention Data used to exhaust
  the documented default budget of 100,000 work units and 16 MiB. Inclusions that
  hold by structure are now established before any automaton is built, with no
  Data-specific rule, and the default limits are unchanged. For example,
  `F: Data => Data` applied to `A: Data` needed at least 544,192 work units and
  now needs 6,189, and a module with both reported cases no longer exceeds
  16 MiB. Checks that completed before keep their verdicts. (2e28b52, #39)
- **Test suite.** The declarations layer has its own tests (#39):
  - the structural kind engine against the [kinds specification](../spec/kinds.md);
  - module admission, pins and imports, and the bundled `horos.kinds` module;
  - application, saturation, constructor contracts and ground specialisation;
  - limits, atomic failure, sealed handles and immutable snapshots;
  - Go-materialised ground descriptors, which the TypeScript checker must judge
    the same way from both the in-repo package and the published one.

## Distribution and evidence

npm `@bitspark/horos@0.11.0`, crates.io `bitspark-horos@0.11.0` (library `horos`)
and `github.com/Bitspark/horos/core/go@v0.11.0`. Root `v0.11.0` and
`core/go/v0.11.0` identify the same accepted source commit. npm and crates.io go
from 0.9.0 to 0.11.0: the Go module already used v0.10.0 (retracted), v0.10.1 and
v0.10.2 for Go-only releases, and one version across all registries is the rule
this release restores.

The release workflow requires all six source checks on the accepted commit, an
exact-source rehearsal, immutable package archives and verification by fresh
anonymous public consumers. The receipts record the actual source, the artifact
hashes and the checks; this document alone does not establish publication.
Historical releases are unchanged. See the
[distribution process](../distribution.md).
