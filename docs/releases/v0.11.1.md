# horos 0.11.1

This release fixes a denial-of-service exposure in every package: the work a check
did was not bounded by the size of its input. A descriptor whose union or
intersection alternatives overlap made `conforms`, `diagnose` and their equivalents
check one value along many routes, doubling the work with every level of the value.
A small descriptor and a value of a few dozen bytes could keep a checker busy for
hours. Upgrade if you check values from an untrusted source.

## Checking work is bounded by the input (ADR 0013)

Within one check, each value is now checked against each node of the written
descriptor at each depth at most once, however many routes reach that pair. A
check does work polynomial in the sizes of the value and the descriptor. No budget
was added: every verdict, every diagnosis and its location, the depth bound, the
checking profile and every API are unchanged. Lexical `ref` resolution (ADR 0011,
0.11.0) is what makes the reuse sound: a descriptor node's position fixes the
bindings it is checked under. TypeScript and Python also check a subvalue shared
between several places in memory only once.

[ADR 0013](../architecture/decisions/0013-bounded-checking-work.md) records the
class, the reuse key, why it is sound and the cost bound. The hand-authored
`vectors/checking-work.json` pins overlapping descriptors against values 64 levels
deep, which every implementation now finishes at once.
