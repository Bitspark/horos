# horos 0.11.1

This release fixes a denial-of-service exposure in every package: the work a check
did was not bounded by the size of its input. A descriptor whose union or
intersection alternatives overlap made `conforms`, `diagnose` and their equivalents
check one value along many routes, doubling the work with every level of the value.
A small descriptor and a value of a few dozen bytes could keep a checker busy for
hours. Upgrade if you check values from an untrusted source.

The advisory is
[GHSA-8vh5-2mqc-56h3](https://github.com/Bitspark/horos/security/advisories/GHSA-8vh5-2mqc-56h3)
(medium severity, CWE-407: inefficient algorithmic complexity). It affects
`@bitspark/horos` on npm, `bitspark-horos` on crates.io and the Go module
`github.com/Bitspark/horos/core/go`, at 0.11.0 and every earlier version. It is
patched in 0.11.1.

## Upgrade

```sh
npm install @bitspark/horos@0.11.1
cargo add bitspark-horos@0.11.1
go get github.com/Bitspark/horos/core/go@v0.11.1
```

The upgrade from 0.11.0 is a drop-in: the APIs, every verdict, every diagnosis and
its location, and the dependencies are unchanged. Every package still requires
public Ontos 0.17.0. The Python validation lane carries the same fix in source.

## Checking work is bounded by the input (ADR 0013)

Within one check, each value is now checked against each node of the written
descriptor at each depth at most once, however many routes reach that pair. A
check does work polynomial in the sizes of the value and the descriptor. No budget
was added: every verdict, every diagnosis and its location, the depth bound, the
checking profile and every API are unchanged. Lexical `ref` resolution (ADR 0011,
0.11.0) is what makes the reuse sound: a descriptor node's position fixes the
bindings it is checked under. TypeScript and Python also check a subvalue shared
between several places in memory only once. Results are kept only below a union
or intersection of two or more alternatives; everywhere else each pair is reached
along one route, so a check there costs what it did before.

[ADR 0013](../architecture/decisions/0013-bounded-checking-work.md) records the
class, the reuse key, why it is sound and the cost bound. The hand-authored
`vectors/checking-work.json` pins overlapping descriptors against values 64 levels
deep, which every implementation now finishes at once.

A check still does work proportional to the sizes of the value and the descriptor,
so callers that accept untrusted values should bound their size before checking,
for example with ontos's `measure`. A default work budget was considered and not
added: it would turn large valid values into `false` or `exhausted`.

## Also in this release

None of these changes an API or a verdict.

- [ADR 0012](../architecture/decisions/0012-mixed-inhabitation.md) specifies how
  a mixed value inhabits a materialized Descriptor, with the corpus
  `vectors/mixed-inhabitation.json` (#51).
- Seeded conformance stresses `rec`/`ref` scoping and runs the Python lane as a
  fourth core (#50); the crate's `horos-fuzz` development tool generates those
  descriptors.
- The Go declarations layer is fuzzed for panics, honoured limits, determinism and
  well-formed ground output (#49), and its materialized ground descriptors are
  checked against the published 0.11.0 (#52).
