# horos 0.9.0

This breaking release replaces the two declaration profiles with one revision-2
Horos declaration language. Every canonical parameter has an explicit Type or
Data bound. `Page<T>` is authored once; `DataPage<D: Data> = Page<D>` restricts
arguments without copying the record, wrapping its values or changing its binder.

## Migration

- Use `horos/decl/module` revision 2 and `horos/decl/parameter(name, bound)`.
  Old ground slots become Data; old mixed slots become Type. Repin imports from
  the rewritten canonical module bytes, preserving literal payloads.
- Use unified `horos/` structural types and `horos/wire(message)` directly.
  Remove the former schema-level Data wrapper. Ontos value embedding is unchanged.
- Consume `core/go/declarations` for all declarations. The old `core/go/wire`
  package and its Embed API are removed without aliases or legacy readers.
- Use TypeParameter metadata, symbolic bound checking and `Program.Specialize`.
  Use `Program.DataDescriptor` when the result must be passed to ground WF/Conforms.

Data-only constructor requirements are explicit; ground any and complements
retain their data universe. Parameters remain lexical, applications keep caller
bindings, and actual parameter use determines data classification. Open bound
violations fail at resolution; no successful specialization can conceal them.
Function, Stream, Cell and new contracts remain ordinary pinned libraries. No
native generators, runtime bindings or live capability validator are introduced.

The authored tests cover nested/imported pagination, Data-bound aliases, phantom
parameters, argument/result classification, open forwarding, literal opacity,
recursion boundaries, diagnostics and bounded work. The ground oracle and all
cross-language conformance checks remain unchanged.

## Distribution and evidence

Versions remain aligned across npm, crates.io and the Go module. Only Go exposes
the declaration tooling; Rust and TypeScript retain ground APIs. Dependencies
remain public Ontos 0.16.0, with Bitwire 0.7.0 in consumer qualification only.
Root v0.9.0 and core/go/v0.9.0 identify the same accepted source commit.

The maintained workflow requires all six source checks, an exact-source rehearsal,
immutable package archives and fresh anonymous public consumer verification.
Receipts record the actual source and artifact hashes; this document alone does
not establish publication. Historical releases remain unchanged. See the
[distribution process](../distribution.md).
