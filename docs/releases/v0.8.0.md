# horos 0.8.0

This release removes template lifting completely. The owner's 4 November 2026
direction is to author generics directly in the profile that owns their parameter
domain, rather than copying ground declarations into optional ones.

## Breaking Go API removal

- Remove `wire.Lift`, `LiftOptions`, `DefaultLiftOptions`, `LiftingRevision`,
  `Derivation`, `DerivedModule` and their exclusive naming/mapping metadata.
- Remove `wire.UnsupportedLift` and the ground declaration `Program.Close` helper
  used only to close source subtrees during lifting.
- Remove the implementation, its tests and exclusive internal work/provenance
  machinery. No compatibility alias, fallback, archive package or replacement
  template transformer is provided.

Author mixed-capable `Page<T>` directly in horos/wire. The same declaration accepts
`Data(Person)` and `Wire(Data(Person))`, or ordinary library-owned Cell types.
Existing ground declarations remain data-only. Both profiles retain resolution,
lexical generic binding, immutable imports and specialization. `wire.Embed`
remains the separate operation that specializes a ground declaration and wraps
its closed descriptor in Data; it creates no optional declaration.

The optional grammar, ground descriptor meanings, original conformance oracle,
Ontos 0.16.0 dependency, transport and hydration semantics are unchanged. Function,
Stream and Cell remain library-owned. No native generator or runtime adapter is
introduced. Bittype removes its corresponding transformer and consumes this release.

## Distribution and evidence

The supported packages remain `@bitspark/horos` on npm, `bitspark-horos` on
crates.io and `github.com/Bitspark/horos/core/go` through the Go proxy. Rust and
TypeScript still expose the ground descriptor APIs; only Go has the declaration
packages. Versioning stays aligned across packages. Root `v0.8.0` and nested
`core/go/v0.8.0` identify the same accepted source revision.

The maintained release workflow requires all six source checks, an exact-source
rehearsal and immutable candidate archives. Publication verifies artifact equality
and fresh anonymous installed consumers before creating the release receipt.
Candidate and published verification receipts identify their actual source and
checks; this document alone does not establish successful publication. The
[distribution guide](../distribution.md) describes the process. Historical 0.7.0
tags, archives and receipts remain unchanged.
