# 0.7.0

Horos now requires public Ontos 0.16.0 in Go, Rust and TypeScript. The Python
validation lane also uses the 0.16.0 source. Upgrade consumer dependencies
together; this release provides no old-version fallback, compatibility export,
private value copy or constructor coercion. Ground descriptors, value identity,
codec bytes and the independently authored conformance corpus are unchanged.

The Go module includes the previously implemented `declarations` package for
modules, generic binding and specialization, and optional `wire` for static
mixed-type declarations and explicit lifting. Rust and TypeScript continue to
provide ground descriptor checking and diagnostics. Horos does not acquire a
live Wire value dependency or implement hydration, request/reply or streaming.
Function, Stream and Cell remain library-owned declarations and behavior.

The release follows the existing six-target CI matrix,
exact-source rehearsal and anonymous installed-consumer verification. A new
TypeScript consumer installs Ontos 0.16.0 and Bitwire 0.7.0 together with Horos,
checks one Atom/Tuple constructor family, ground codec/conformance exchange and
the static separation of ground and mixed inputs. Bitwire is test-only. Go and
Rust installed consumers select Ontos 0.16.0 without local dependency overrides.

Root `v0.7.0` and nested `core/go/v0.7.0` identify the same release commit.
Package publication does not migrate or deploy services. Earlier immutable
release artifacts remain historical evidence, not an alternate supported path.

## Diagnosing trusted publication

The [release workflow](../../.github/workflows/release.yml) has a `diagnose` mode
for the accepted `candidate_run`. It retains the rehearsal, exact source CI,
tag and archive checks and uses the same `release.yml` identity and `release`
environment as publication. The candidate source is checked out separately from
the diagnostic's workflow revision. Neither its archives nor its tags change.

The [diagnostic](../../scripts/diagnose-npm-oidc.cjs) invokes the unmodified native
npm publisher with forced `--dry-run` and scripts disabled. npm performs its
normal GitHub identity-token request, registry exchange and credential lookup
before skipping the upload. A successful dry-run exit alone does not establish
authentication: the report requires the native exchange-success message, no
missing-credential warning and completion of the dry-run. This is diagnostic
evidence, never proof of package publication or provenance generation.

The comparison between npm 11.19.1 (the failed upload client) and 12.2.1 isolates
client behavior; it is not an alternate publishing path. The harness refuses
injected identity tokens and reusable npm token environment variables. It adds no
auth configuration and keeps the runner's setup-node configuration for both
clients. Output consists only of fixed stage labels, numeric statuses, allowlisted
error codes and presence booleans. Native output is captured without streaming,
disk debug logs are disabled, and raw provider bodies, request URLs, credentials
and configuration are never printed or uploaded. The public CI lane runs
[tests](../../scripts/test-diagnose-npm-oidc.cjs) for those output and invocation
constraints. Final delivery still requires the existing publish and independently
installed-consumer verification stages.
