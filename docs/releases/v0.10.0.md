# horos Go 0.10.0

This breaking Go release replaces closed Type/Data claims with general
structural kinds in declaration revision 4. Scalar, List, Record and Data are
ordinary definitions. Users can define, import, parameterize and combine kinds
through the same machinery, including guarded recursive kinds and constructor
contracts. Constructor inputs and results may themselves be constructors.

```text
kind Flat = Scalar | List<Scalar>
kind Rows = Record<Flat>
kind Tree = nu X. Scalar | List<X> | Record<X>

Page<T> = { items: list<T>; next?: text; }
Alias : Type -> Type = Page
Later<F: Type -> Type> : Type -> Type = F
```

These equations illustrate meaning; Bittype supplies readable source syntax.
Known constructors retain checked bodies, enabling requested guarantees such as
Page : Data -> Data and Page : Scalar -> Rows. Abstract constructors expose
finite joint or alternative arrow contracts. Original input admission is
preserved, including ignored arguments. There is no principal-kind or complete
higher-order inference claim.

## Migration

- Use module revision 4. Kind declarations and type declarations share one
  module namespace. Type parameters and results contain kind expressions;
  kind parameters carry finite simple sorts. Earlier readers and the fixed
  Claim/Interface/DataSummary API are removed without aliases.
- Use local/imported declaration references directly. An application contains a
  callee expression and a nonempty argument list. A zero-parameter declaration
  is a reference, and may denote a constructor. Each application saturates one
  nonempty parameter list; a result may be applied again.
- Repin canonical documents after migration. Exact module bytes and declaration
  names retain identity; literals remain opaque and never become generic syntax.
- Import the ordinary horos.kinds prelude explicitly when using its names.
  A same-spelled local Data or Type has no special meaning. Primitive operand
  contracts use the bundled definitions by identity.
- Use Program.Value, Proper and Apply with sealed values from the same Program.
  Descriptor materializes a proper result. GroundDescriptor additionally
  establishes the ordinary ground-kind obligation and existing WF.
- Use CompileKind with an explicit module context, Satisfies and Includes for
  queries. Proven, Refuted and Unproved are distinct; malformed requests and
  resource exhaustion remain errors. Failed free-shape inclusion is not an
  admitted Horos counterexample.
- Read the [canonical specification](../spec/declarations.md) and
  [Go API](../../core/go/declarations/README.md) for exact signatures and rules.

Partial application, type lambdas, growing recursive kind applications,
quantified constructor schemes and arbitrary subtree predicates remain outside
this revision. Higher-order native encodings belong to explicit Bittype
representation profiles. This release adds no runtime bindings.

## Preserved boundaries

Ground Ontos/Horos values and conformance are unchanged. Data preservation does
not establish recursion guardedness. Capability hydration, transport, execution
and library protocols retain their existing owners. Function, Stream and Cell
remain ordinary libraries; no core behavior or adapter is introduced.

Only Go exposes declaration tooling. Rust and TypeScript retain their existing
ground APIs. This delivery publishes the Go module tag core/go/v0.10.0 for
Bittype's dependency; it does not publish npm or Cargo packages. Ontos remains
0.16.0. A broader distribution release is a separate operation.

No validation, checksum or provenance workflow is added or run under the owner's
current delivery rule. Unrun checks are not reported as passing.
